## Problem and read-before-edit

`src/cli/main.py` lets `fetch-topic` and `case rerun` use `--output`; `src/cases/service.py` publishes under the run's output directory and stores paths. `src/http/app.py:get_artifact_output_root` uses only `Path("./output")`; `src/http/dependencies.py` separately passes the same literal to `build_case_service`. The list route intentionally does not prove file existence, so a valid CLI artifact can be listed and then be unavailable to HTTP under the wrong root. Existing artifact tests override the dependency, hiding configuration mismatch. Read `src/cases/artifact_reader.py`, the publication path construction, `src/runtime.py`, CLI serve/rerun options, `tests/test_refinement_artifact_reader.py`, and the V01 fixture script.

## Contract and implementation outline

1. Add a single operator setting **`TRIANGULATE_OUTPUT_ROOT`** for the HTTP server. When not set or blank, use `./output`. Resolve configured relative paths against the documented server startup working directory. Capture the setting consistently for an app/runtime instance, not from query/body/header data or from artifact rows. Wire it into both HTTP artifact reads and the HTTP case-service root. It must not trigger `mkdir`, write, or fix paths as part of a read. CLI publication keeps existing `--output` or default behavior; document passing the same absolute directory to CLI and HTTP. No need for a second config knob or change in writer format.
2. Ensure existing legitimately published path forms work: default relative record (e.g. `output/cases/...`), matching relative custom root when writer and server have the same cwd, and absolute custom root. Normalize relative versus absolute representations **lexically** against the documented cwd if necessary; reject unsafe components before normalization, and don't infer another root from a record. Match the exact expected path derived from configured root + verified case slug + run ID + fixed filename. If a legacy custom relative path was recorded from a different cwd and cannot be attributed safely, fail closed with existing uniform `404`; document the stable absolute-path workflow, do not rewrite or search alternative locations.
3. Preserve the same case/run/stage ownership join and successful-run requirement; allowlisted artifact types, fixed names, no-follow descriptor walk below the trusted case-directory anchor, regular-file and size limits, one checked/read handle, attachment headers, checksum meaning, and redacted uniform failure body. Do not weaken containment to support more path forms. No content from sibling runs, current/latest reports, arbitrary file names or caller-supplied roots. Keep list semantics (`200 []` when no published artifacts for a known run; eligible descriptors are metadata, not a promise that bytes exist).
4. Update `docs/reference/http-api.md`, the documented serve/CLI flow, and `.env.example` if it documents serve settings. Shell example (disposable values only): use `... --output "$SCRATCH/output"` at publication and `TRIANGULATE_OUTPUT_ROOT="$SCRATCH/output" uv run triangulate serve --host 127.0.0.1 --port <isolated-port>` with the matching scratch database configured per R05. No request/API-field change; no repository `.env`, real configuration, or artifacts.
