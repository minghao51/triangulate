## Contract

1. Keep existing missing/wrong-case uniform `404`, bad request/order `422`, and row-level schema → identity → policy/unknown availability precedence. Only after the pair has a supported, compatible row version, check **both** frozen payloads before constructing any items. An unreadable payload must never reach semantic indexing as an empty observation.
2. For `case-snapshot-v1`, require a mapping, the owning `caseId`, matching embedded schema/identity/policy markers, the case facts consumed by the semantic projection (`query`, nullable `reviewNotes`), and all entity arrays emitted by its writer and used in the delta: `articles`, `events`, `claims`, `links`, `citations`, `evidence`, `captures`, `reviews`, `exceptions`, `parties`, `partyInvestigations`, `narratives`. A legitimately empty array is valid; missing/null/not-a-list is not. Each item must be a mapping with a nonblank string ID unique within its group. Don't turn nullable/unknown observation metadata into mandatory values or require unrelated live foreign keys; preserve historically valid frozen references.
3. Check content consistency against the stored semantic hash using the canonical writer projection on supported payloads, after shape validation. This detects truncated groups, missing semantic fields and changed contents even if the shape still looks valid; it is consistency checking, **not** authentication or tamper-proof verification. Counts, timestamps and nonsemantic metadata do not become comparable fields. Use the existing projection/hash behavior; avoid computing the same projection repeatedly. If a verified historical writer format uses divergent markers/shape/hash under the same v1 row metadata, stop and document the exact supported variant rather than grandfathering arbitrary partial payloads or recomputing hashes on disk.
4. For unreadable data return HTTP `200` with existing `availability: "unavailable"`, `unavailableReason: "payload_unreadable"`, `items: []`, `total: null`, `hasMore: false` and intact selected ID/metadata and paging fields. No raw row contents, errors, current-state fallback or repairs in that response. Handle malformed stored JSON decoding at the read boundary if applicable; keep unrelated database/runtime failures distinct from unreadable payloads. Do not broadly catch database exceptions and turn them into found/unavailable results.
5. Preserve zero changes for two well-formed equal observations, legitimate `entity_added`/`entity_absent`, field changes, stable ordering and pagination, side-scoped frozen refs, and coverage wording. Do not change `build_snapshot_delta`, persisted recorded-run `/changes`, or published policy version just to validate reader inputs. The reader must remain read-only; no migration/new column/index/write.
